# FaceCheck AI 使用日志

## 一、使用说明

本项目开发过程中使用 AI 编程助手辅助完成需求拆解、代码实现、问题定位、文档整理和构建验证。AI 主要承担辅助角色，关键功能均通过人工提出需求、真机验证和多轮修正后确定。

AI 未替代人工判断，尤其是以下内容均由人工确认：

- 项目需求范围
- 课表来源
- 原型视觉方向
- 真机运行结果
- 活体检测和人脸比对接口职责
- 最终功能是否可验收

## 二、AI 使用原则

1. 先阅读项目文档和现有代码，再修改实现。
2. 每一阶段先明确目标，再进行代码修改。
3. 对真实设备问题，通过最小项目单独验证。
4. 对 AI 生成代码进行构建检查和真机测试。
5. 对接口理解错误及时修正，不把模拟逻辑伪装成真实识别。
6. 文案、UI 和统计逻辑根据人工反馈多轮调整。

## 四、关键问题与 AI 辅助解决过程

### 1. DevEco 命令行工具不可用

问题：命令行无法直接调用 `hvigor`、`ohpm`。

AI 辅助：

- 根据 DevEco Studio 安装目录查找工具链
- 配置 `NODE_HOME`、`DEVECO_SDK_HOME` 和 `PATH`
- 使用 Hvigor 命令构建项目

结果：项目可在命令行完成 HAP 构建。

### 2. 前置摄像头采集异常

问题：人脸录入页授权后停留，点击采集后没有结果，部分链路出现闪退。

AI 辅助：

- 建立最小相机项目
- 先验证前置摄像头预览
- 避免继续使用不稳定的 `PhotoOutput` 解码链路
- 改用预览 Surface 截取当前帧

结果：前置预览和当前帧采集可用于录入和识别。

### 3. 活体检测成功却显示失败

问题：系统活体检测成功返回后，应用仍显示失败或出现属性读取错误。

AI 辅助：

- 识别 `code = 0` 实际表示成功
- 增加结果未就绪保护
- 避免读取运行时不存在的 `LivenessType` 对象
- 改用数值 `0/1/2` 判断活体结果

结果：活体检测成功后可正常进入人脸比对页。

### 4. 失败记录重复计入缺勤

问题：同一节课多次刷脸失败会产生多条失败记录，并重复计入缺勤。

AI 辅助：

- 区分失败记录和缺勤统计
- 为缺勤类失败增加标记
- 统计时按课程和日期去重
- 已成功签到的课程不再计缺勤

结果：失败记录可保留，但缺勤次数符合真实业务含义。

### 5. 首页导航图标显示异常

问题：首页图标在非首页状态下不能稳定显示。

AI 辅助：

- 尝试替换 SVG 资源
- 调整模板着色和颜色
- 最终改用 ArkUI 原生 `Path` 绘制
- 按设备反馈继续调整大小

结果：首页图标可显示，并逐步调整到接近其他导航图标大小。

## 五、AI 生成内容的人工复核方式

| 内容 | 复核方式 |
| --- | --- |
| 代码修改 | 使用 Hvigor 构建检查 |
| 相机功能 | 真机运行验证 |
| 活体检测 | 真机启动系统检测流程 |
| 人脸比对 | 使用真实录入图和当前采集图测试 |
| 课程状态 | 检查不同时间窗口下的显示 |
| 缺勤统计 | 检查重复失败是否重复计数 |
| UI 图标 | 通过设备截图和肉眼检查 |
| 文档 | 人工阅读确认是否适合提交 |
