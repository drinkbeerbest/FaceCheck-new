# FaceCheck 项目实作过程

## 一、项目概述

FaceCheck 是一款面向课堂签到场景的 HarmonyOS 学生端应用。项目目标是让学生在移动设备上完成登录、查看课程、人脸录入、活体检测、刷脸签到和签到记录查看。

项目最初以可演示 Demo 为目标，后续逐步接入真实端侧能力。最终版本实现了从本地人脸录入到系统活体检测，再到真实人脸比对和本地签到记录保存的完整闭环。

## 四、整体实现流程

### 1. 搭建学生端 Demo 闭环

第一阶段先完成不依赖真实摄像头和真实人脸接口的可验收 Demo。

主要实现内容：

- 重构首页为 App Shell
- 增加底部导航：首页、记录、个人、设置
- 增加登录页
- 增加人脸录入、活体检测、人脸识别模拟页
- 增加签到记录页
- 增加个人页和设置页
- 使用 Preferences 保存登录状态、人脸录入状态和签到记录

这一阶段的重点是先跑通业务状态流：未登录、已登录、未录脸、已录脸、签到成功、记录展示。

### 2. 整理课程、账号与基础 UI

第二轮优化时，根据新的课表 PDF 更新课程数据，并修复登录态和统计问题。

主要实现内容：

- 新增两个测试账号：
  - `202440011987 / root / 戴奇威`
  - `202440011111 / root / root`
- 将课程数据替换为新课表中的课程
- “我的课表”改为表格视图
- 签到记录、出勤统计按当前学生隔离
- 未登录状态下不再显示默认学生信息
- 底部导航加入图标和文本
- 默认头像使用图标展示
- 修复个人页菜单、设置页列表的文本对齐

### 3. 加入签到窗口规则

首页今日课程卡片根据课程时间显示不同状态：

- 课程开始前：未开始签到
- 课程开始后 10 分钟内：开始签到
- 超过开始后 10 分钟且未签到：未签到
- 已成功签到：已签到

主按钮只允许对当前处于签到窗口内的课程发起签到。这样避免任何时间都能打卡，提升演示逻辑的真实性。

### 4. 接入相机预览与权限

第二阶段开始进入可真机验证能力。

主要实现内容：

- 在 `module.json5` 中声明相机权限
- 进入人脸录入、活体检测、识别流程前请求相机权限
- 使用前置摄像头预览
- 增加相机不可用和权限拒绝提示
- 建立 `FaceCaptureService` 负责预览启动、释放和当前帧采集
- 建立 `FaceService` 门面，隐藏具体识别模式和实现细节

为排查摄像头问题，还单独创建了 `camera-preview-minimal` 最小验证项目，用来验证前置摄像头预览和活体检测是否能单独运行。

### 5. 修正真实人脸接口职责

开发过程中发现最初对人脸接口职责理解不够准确。修正后的流程如下：

#### 人脸录入

录入只负责拍摄并保存一张本地基准人脸图，不调用活体检测，也不调用人脸比对。

#### 活体检测

活体检测只判断当前操作对象是否为真人。系统会拉起检测流程，不需要从检测结果中取图用于比对。

#### 人脸比对

人脸比对需要两张图：

- 本地保存的基准人脸图
- 签到时重新拍摄的当前人脸图

然后调用 `faceComparator.compareFaces()`，根据相似度和是否为同一人判断签到是否成功。

### 6. 实现真实人脸比对闭环

最终的人脸签到流程：

1. 学生登录
2. 未录脸时进入人脸录入页
3. 打开前置摄像头并保存本地基准人脸图
4. 进入签到窗口后点击签到
5. 调用系统活体检测
6. 活体通过后进入人脸识别页
7. 再次打开前置摄像头采集当前人脸
8. 读取本地基准图
9. 调用 `faceComparator.compareFaces()`
10. 相似度达到阈值后写入成功签到记录

比对阈值设置为 `0.75`。同时要求 `isSamePerson === true`。

### 7. 调试与问题修复

开发过程中遇到并解决了多个真机问题：

| 问题 | 原因 | 处理方式 |
| --- | --- | --- |
| 命令行找不到 `hvigor` 和 `ohpm` | 工具未加入环境变量 | 从 DevEco Studio 安装目录配置工具链路径 |
| 摄像头权限可请求但页面停留 | 相机采集链路不稳定 | 单独建立最小项目验证前置预览 |
| `PhotoOutput` 链路闪退 | 图像解码链路在当前设备不稳定 | 改为从预览 Surface 截取当前帧 |
| 活体检测构造失败 | 运行时不支持直接构造配置类 | 改用对象字面量配置 |
| 活体检测成功却显示失败 | 回调中 `code = 0` 被误判为错误 | 将 `code = 0` 视为成功 |
| `LivenessType` 运行时为空 | d.ts 有声明但运行时对象不存在 | 按文档数值 `0/1/2` 判断 |
| 失败打卡重复计入缺勤 | 普通失败记录和缺勤统计混在一起 | 失败记录保留，缺勤按课程日期去重 |
| 首页导航图标不显示 | SVG 模板渲染不稳定 | 首页图标改为 ArkUI `Path` 绘制 |

## 五、数据设计

项目主要数据模型包括：

- `User`：学生基础信息
- `StudentAccount`：本地测试账号
- `Course`：课程信息
- `AttendanceRecord`：签到记录
- `FaceProfile`：本地人脸录入信息

数据存储策略：

- 登录状态使用 Preferences 保存
- 签到记录按学生隔离保存
- 人脸录入状态按学生隔离保存
- 本地基准人脸图保存在应用本机目录
- 设置页可清除当前学生的人脸数据

## 六、测试与验证

使用 Hvigor 构建：

```powershell
hvigorw assembleHap --mode module -p module=entry@default -p product=default
```

构建结果多次达到 `BUILD SUCCESSFUL`。

### 真机验证

验证内容包括：

- 登录两个学生账号
- 前置摄像头预览
- 人脸录入
- 活体检测拉起和返回
- 人脸比对成功
- 非本人或相似度不足时失败
- 签到记录写入
- 退出登录后状态恢复
- 清除本机人脸数据
- 底部导航图标显示

### 统计验证

重点验证：

- 打卡失败记录可以保留
- 同一课程同一天多次失败不会重复增加缺勤
- 只有错过签到窗口且未成功签到时才计入缺勤
- 出勤率基于成功签到和缺勤次数计算

- 今日课程签到状态
- 真实前置摄像头预览
- 本地人脸录入
- 系统活体检测
- 真实人脸比对
- 签到成功和失败记录

- 本机人脸数据清除
- 课表查看
- 基础设置页

## 八、当前限制

当前版本仍有以下限制：

- 不包含教师端
- 不包含服务器端
- 登录账号为本地演示账号
- 课程数据为本地静态数据
- 未实现云端请假、补签、教师审核等功能
- 人脸图只用于本机演示，不做跨设备同步

这些限制符合当前课程设计的学生端 Demo 范围。
